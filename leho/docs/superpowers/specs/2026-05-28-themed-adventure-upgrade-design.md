# 设计文档：主题冒险闯关升级

- 日期：2026-05-28
- 状态：草案，待用户评审
- 分支：`game-upgrade-index-html`
- 范围：升级 `index.html` 的核心游戏体验，让现有 5 题一局变成“当前座驾主题冒险 + 小 Boss 结尾”。

## 1. 背景与现状

当前游戏已经具备以下基础：

- 单页 `index.html`，面向不识字、主要靠听和看 emoji/数字玩的 5 岁儿童。
- 双玩家、5 题一局、20 以内加减法。
- 车库、金币、勋章、装备座驾/恐龙。
- `Garage.vehicleFamily(vehicleId)` 已将座驾映射为 `police / ambulance / fire / everyday / adventure` 五个主题族。
- 题库、庆祝语、飞车文案、称号已经跟当前装备座驾族联动。
- 已有语音 `speak` / `speakQueue`、Web Audio 音效、烟花、金币飞入、全屏飞车动画。

本期不再继续堆普通装饰，而是把核心答题流程升级成“主题冒险闯关”。孩子看到的是冒险、冲刺、Boss、爆炸、奖励；系统底层仍保持 5 题一局和现有数学规则。

## 2. 目标

### 2.1 产品目标

- 让每局游戏更像一次完整冒险，而不是普通答题。
- 让车库更有价值：装备不同座驾后，地图、Boss、音效、通关动画自动变化。
- 强化“再玩一局”的动力：闯关、Boss、奖励、地图推进形成闭环。

### 2.2 硬约束

这些约束是验收门槛，不是可选优化：

- **H1 夸张酷炫动画**：答对、连对、Boss 登场、Boss 受击、Boss 击败、通关奖励都必须有明显动画。不能只是按钮变色或轻微弹一下。
- **H2 每个关键动画必须有音效**：冲刺、攻击、Boss 登场、击败、金币雨、通关都必须有对应 Web Audio 音效。静音按钮只控制语音，不控制特效音，沿用现有警笛行为。
- **H3 所有新文字必须有语音**：地图名、关卡目标、Boss 出场、奖励、按钮、提示、结算新增内容都必须经 `speak` 或 `speakQueue` 播报。
- **H4 不能依赖识字**：核心流程必须靠 emoji、数字、颜色、进度条、动画和语音玩通。文字只能辅助家长理解，不能成为儿童完成操作的唯一信息。

## 3. 非目标

- 不引入乘除法，不扩大到 20 以外。
- 不做复杂自适应教学系统；本期主线是好玩。
- 不做每辆车一套独立地图；按五个座驾族做，控制内容量。
- 不重写车库、勋章、金币经济；只接入现有系统。
- 不改一局 5 题的基本节奏。

## 4. 核心体验

选玩家后，进入当前装备座驾族对应的冒险场景。每局仍然是 5 道题，但每道题都是冒险的一步：

1. **冒险入场**：显示当前主题地图，座驾和恐龙准备出发；语音播报主题和目标。
2. **第 1-4 题冲刺段**：答对后，座驾在地图上冲刺一段，带拖尾、震屏、粒子、金币飞入和主题音效。连对越多，速度、粒子密度、震屏幅度越强。
3. **第 5 题 Boss 段**：进入最后一题前 Boss 夸张登场；答对后触发终结技。
4. **大结算动画**：Boss 被击败或逃跑，全屏烟花、金币雨、座驾凯旋、语音连续夸奖，再进入现有结果页。

错题不推进地图。孩子答错后仍按现有规则重试，语音鼓励，不惩罚星星以外的冒险状态。只有首次答对一题时，地图进度和金币奖励推进一次。

## 5. 五个主题冒险

地图按 `Garage.vehicleFamily(getPlayerGarage(playerId).equippedVehicle)` 自动选择。

### 5.1 警车主题 `police`

- 场景：城市追捕路线。
- 目标：追上捣乱车，完成破案。
- Boss：黑色捣乱车 / 坏蛋车队。
- 冲刺动画：警车警灯扫屏、红蓝闪烁、路障飞开、速度线。
- 攻击动画：警灯冲击波撞向 Boss，Boss 冒星星后后退。
- 终结动画：Boss 被警灯圈住，路障升起，烟花爆开。
- 音效：现有警笛增强版 + 撞击低频 + 胜利三音。
- 语音示例：`警车出动！追上捣乱车！`、`破案成功！太厉害了！`

### 5.2 救护车主题 `ambulance`

- 场景：医院急救路线。
- 目标：穿过城市，把急救能量送到终点。
- Boss：病毒云 / 堵路病菌。
- 冲刺动画：救护车闪灯、绿色治疗光点、道路打开。
- 攻击动画：治疗光波冲向 Boss，Boss 变小、颜色变淡。
- 终结动画：病毒云被净化成星星和爱心，医院灯光亮起。
- 音效：现有救护车警笛 + 治疗上升音 + 柔和胜利和弦。
- 语音示例：`救护车加速！急救能量来了！`、`急救成功！你是小英雄！`

### 5.3 消防主题 `fire`

- 场景：消防救援路线。
- 目标：扑灭大火，救出小猫。
- Boss：火焰怪。
- 冲刺动画：消防车冲出车库、水管展开、火星飞散。
- 攻击动画：高压水柱横扫屏幕，火焰 Boss 被浇小。
- 终结动画：火焰变成蒸汽云，云里爆出小猫、星星、金币。
- 音效：消防铃 + 水柱喷射噪声 + 蒸汽“噗”声 + 胜利铃声。
- 语音示例：`消防车出动！快去灭火！`、`火灭啦！救援成功！`

### 5.4 出行主题 `everyday`

- 场景：城市交通路线。
- 目标：安全到站，冲破堵车。
- Boss：大堵车 / 路障堆。
- 冲刺动画：校车/出租车/火车/拖拉机沿道路前进，乘客星星跳起来。
- 攻击动画：喇叭声波推开路障，车辆队伍让路。
- 终结动画：终点站灯牌亮起，乘客星星和金币从车门跳出。
- 音效：友好喇叭双音 + 车轮加速 + 站台到达提示音。
- 语音示例：`安全出发！快到下一站！`、`安全到站！棒极了！`

### 5.5 探险主题 `adventure`

- 场景：太空/竞速路线。
- 目标：穿过陨石区，抵达终点。
- Boss：大陨石 / 太空障碍。
- 冲刺动画：火箭/赛车/直升机/飞碟高速穿屏，星轨、喷焰、镜头震动。
- 攻击动画：发射冲击波或喷焰，陨石裂开。
- 终结动画：陨石爆成彩色星云，车辆穿过星门，满屏金币雨。
- 音效：点火轰鸣 + 上升 whoosh + 爆裂音 + 太空胜利音。
- 语音示例：`准备发射！冲过陨石区！`、`抵达终点！超厉害！`

## 6. 页面与流程改动

### 6.1 新增冒险 HUD

在答题页顶部或题卡后方增加轻量冒险 HUD：

- 当前主题 emoji。
- 5 段进度点，前 4 段为路点，第 5 段为 Boss。
- 当前座驾 emoji 在进度线上移动。
- Boss 血量用 1 个大图标 + 数字/颜色表示，不依赖文字。

HUD 文字必须可被语音播报；儿童操作不能依赖读文字。

### 6.2 冒险入场

`startGame()` 生成题目后，先触发主题入场：

- 背景切到主题场景色和图形。
- 座驾从屏幕边缘冲入。
- 播放主题启动音效。
- `speakQueue` 播放目标，例如：`消防车出动！答对五题，打败火焰怪！`

入场动画必须可跳过或不阻塞答题。若用户快速点击，状态不能错乱。

### 6.3 答对冲刺

在 `submitAnswer()` 首次答对分支中，现有金币飞入、庆祝、飞车逻辑改造为主题冒险动作：

- 第 1-4 题：播放 `showAdventureStep(...)`。
- 第 5 题：播放 `showBossFinisher(...)` 后进入 `showResult()`。
- 答对仍保留当前计分、金币、tagScores、勋章逻辑。

连对越高，动画参数越夸张：

- `correctStreak = 1`：普通冲刺。
- `correctStreak = 2-3`：拖尾增强、粒子更多。
- `correctStreak >= 4`：震屏、全屏闪光、双层音效。

### 6.4 Boss 登场

第 5 题渲染前触发一次 Boss 登场动画：

- 全屏短暂压暗。
- Boss 从远处放大砸入。
- 主题警报/鼓点音效。
- 语音播报 Boss 名和目标。

登场只在每局第 5 题出现一次，避免重复重试时不断打断孩子。

### 6.5 通关结算

第 5 题答对后：

1. 终结技动画。
2. Boss 击败动画。
3. 金币雨和烟花。
4. 语音夸奖和奖励播报。
5. 进入现有结果页。

结果页保留现有星星、金币、勋章、去车库按钮。新增冒险通关语音必须接入现有结果语音队列，不能互相掐断。

## 7. 技术设计

### 7.1 主题配置表

在 `index.html` 增加 `ADVENTURE_THEMES`，按 family 存配置：

```js
const ADVENTURE_THEMES = {
  police: {
    name: '警车追捕',
    mapEmoji: '🏙️',
    bossEmoji: '🚧',
    bossName: '捣乱车',
    introLines: [...],
    stepLines: [...],
    bossLine: '捣乱车来了！答对这一题，抓住它！',
    victoryLine: '破案成功！太厉害了！',
    sounds: { intro: playPoliceStart, step: playPoliceBoost, boss: playBossAlarm, hit: playPoliceHit, victory: playVictoryBurst }
  }
};
```

实现时优先抽共享结构，避免五套逻辑复制。文案可分主题不同，但状态机一致。

### 7.2 冒险运行态

新增每局内存态，不持久化：

```js
let adventureRun = {
  family: 'fire',
  step: 0,
  bossShown: false,
  completed: false
};
```

`startGame()` 初始化；`renderQuestion()` 根据 `currentIdx` 和 `adventureRun` 更新 HUD；`submitAnswer()` 首次答对后推进 `step`。

本期不持久化地图进度，避免扩大存档和清除记录语义。每一局都是一次完整冒险。

### 7.3 动画函数

新增三个核心动画入口：

- `showAdventureIntro(theme, vehicleEmoji, dinoEmoji, done)`
- `showAdventureStep(theme, vehicleEmoji, dinoEmoji, step, streak, done)`
- `showBossFinisher(theme, vehicleEmoji, dinoEmoji, streak, done)`

每个函数必须：

- 有 reduced-motion 降级。
- 有超时兜底调用 `done`。
- 不直接改分数、金币、题目状态，只负责表现。
- 调用对应音效。
- 对需要播报的文字调用 `speak` 或 `speakQueue`。

### 7.4 音效函数

新增或复用 Web Audio 合成音效：

- `playAdventureIntro(family)`
- `playAdventureBoost(family, streak)`
- `playBossEntrance(family)`
- `playBossHit(family)`
- `playBossDefeat(family)`
- `playRewardRain()`

原则：

- 不引入外部音频文件，继续使用 Web Audio 合成。
- 不受 `voiceMuted` 控制，保持现有警笛一致性。
- 所有音效函数内部容错，AudioContext 不可用时静默失败，不阻塞流程。

### 7.5 语音接入

所有新增文字集中放入主题配置或语音函数，禁止散落裸字符串后忘记播报。多句场景必须用 `speakQueue`：

- 冒险入场目标。
- Boss 登场。
- 通关奖励。
- 新按钮或新提示。

单句即时反馈可用 `speak`。任何新 DOM 文案都必须能追溯到对应语音。

## 8. UI 与视觉原则

- 答题区仍保持大数字、大按钮，不能让冒险 UI 挤压核心答题。
- 冒险 HUD 使用 emoji、进度点、颜色、动画表达，不把长文字放到孩子必须读的位置。
- Boss 血量/终点状态用大图标和数字表达。
- 每个主题有明显色彩和运动差异，但不能改成过暗或过乱导致数字看不清。
- 动画可以夸张，但题目数字、输入区、确认按钮必须稳定可见。

## 9. 数据与兼容性

- 不改变 `dino_math_records` 结构。
- 不改变 `dino_math_garage` 结构。
- 不改变金币和星星计算。
- 不改变 `Garage.vehicleFamily`。
- 冒险状态只存在当前局内存，刷新页面即重新开始。
- 清除记录仍按现有语义清空 records、names、garage。

## 10. 测试与验收

### 10.1 自动化/逻辑检查

新增项目内自检清单 `docs/superpowers/plans/2026-05-28-themed-adventure-acceptance-checklist.md`，至少覆盖：

- 逻辑是否一致：一局 5 题、错题不推进、首次答对才推进、第五题 Boss 只出现一次、结算只执行一次。
- 动画是否足够酷炫：答对/连对/Boss 登场/Boss 击败/奖励必须有明显全屏或局部强反馈。
- 动画是否有音效：每个动画入口必须调用对应音效函数或显式说明复用现有效果。
- 视觉是否仅依赖文字：任何新增文字都必须有语音；儿童关键操作必须能靠 emoji、数字、颜色、进度、语音完成。

### 10.2 浏览器验收

每个 family 至少验收一次：

1. 装备该族座驾。
2. 进入游戏，确认冒险入场动画、音效、语音。
3. 答对第 1 题，确认冲刺动画、金币、音效。
4. 连续答对，确认连对增强。
5. 到第 5 题，确认 Boss 登场只出现一次。
6. 通关，确认终结技、Boss 击败、烟花、金币雨、语音。
7. 静音语音后，确认语音静默但视觉仍可玩；音效行为与现有警笛一致。
8. reduced-motion 下，确认动画降级但流程、得分、结算正确。

### 10.3 回归验收

- `node --test tests/garage.test.js` 必须通过。
- 默认乐乐警车、昊昊救护车仍进入正确 family。
- 现有车库、金币、勋章、排行榜、清除记录不回归。
- 现有题库和主题题概率不因冒险 HUD 改动而改变。

## 11. 自检规则

实现完成前，必须逐项回答并在验收清单中打勾：

1. **逻辑一致性**：新冒险状态是否只跟当前局相关？是否没有破坏得分、金币、星星、勋章？
2. **动画强度**：每个关键节点是否有孩子能明显感知的运动、粒子、震屏、闪光或全屏变化？
3. **音效覆盖**：每个关键动画是否同步触发音效？音效失败是否不会卡住流程？
4. **语音覆盖**：每个新增文字和状态是否都有语音？多句是否走 `speakQueue`？
5. **非文字可玩**：关卡目标、进度、Boss 状态、奖励是否能靠 emoji、数字、颜色、动画理解？
6. **节奏不过载**：动画是否夸张但不遮挡题目输入？是否有超时兜底和 reduced-motion 降级？
7. **五族一致性**：五个 family 是否都有地图、Boss、冲刺、终结、音效、语音，不存在某族偷懒缺项？

## 12. 可调项

- Boss emoji 和名称。
- 各主题音效参数。
- 冲刺和 Boss 动画时长。
- 连对增强幅度。
- 入场语音和胜利语音文案。
- 是否在结果页展示本局冒险主题徽章。

默认建议：第一版把每局体验做完整，不新增长期地图存档。先证明“每局都更好玩、更酷炫”，再考虑第二期做章节地图和长期进度。
