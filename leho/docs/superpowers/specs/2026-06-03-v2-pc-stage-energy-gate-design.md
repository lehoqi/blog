# V2 PC 左侧舞台：数字钥匙能量门设计

## 1. 目标

把 V2 PC 端答题页左侧从“装饰性舞台”升级为“孩子能看懂、愿意期待下一题的动画关卡”。

孩子每答对一题，都要感到自己不是只输入了答案，而是用答案数字触发了冒险推进：数字变成钥匙，打开能量门，座驾穿门进入下一段。第 5 题升级为 Boss 护盾战，答案数字击碎护盾后触发终结星门。

本设计不改题型、不改答题规则、不重做右侧题目区，不做手机端专项适配。实现重点是 PC 端左侧舞台的画面、动效、声音和故事反馈。

## 2. 设计原则

1. **数学驱动冒险**  
   答案数字必须成为动画主角。孩子要看懂“我算出的数字让门打开了”，而不是看到一个与答题无关的闪光效果。

2. **精致，不乱闪**  
   动效要有层次：待机轻动、答对强反馈、连对升级、终局爆发。高亮、粒子和震动只在关键时刻出现，避免一直闪导致题目注意力被抢走。

3. **声音与动作同步**  
   声音不是背景噪音，而是动画节拍的一部分。数字飞出、门解锁、座驾穿门、Boss 护盾破裂、终结技都要有明确声音节点。

4. **儿童友好**  
   主题可以刺激，但不走“暴力撞击”。用开门、穿越、破解护盾、救援通道等表达成功，保留酷炫感，同时更适合儿童。

5. **可降级**  
   如果浏览器不支持音频、用户关闭声音或启用减少动态效果，游戏仍然能清楚表达进度。

## 3. 核心体验

### 3.1 出题待机

左侧舞台显示：

- 当前座驾和恐龙组合。
- 当前主题背景。
- 远处的能量门轮廓。
- 5 个关卡节点。
- 能量条。
- 第 5 题前隐藏 Boss 护盾，仅保留远处威胁感。

待机动效：

- 背景有慢速景深流动。
- 能量门轻微呼吸发光。
- 座驾悬浮或轻微怠速。
- 当前关卡节点轻闪。

声音：

- 默认不持续播放背景音乐。
- 可以有极轻的待机环境音，但必须可静音，且不能影响题目朗读。

### 3.2 答对普通题

答对后进入短动画，目标时长约 900-1300ms：

1. 右侧答案数字复制为舞台粒子数字。
2. 数字从题目区飞向左侧能量门。
3. 能量门吸收数字，门环旋转并点亮。
4. 座驾带尾焰穿过能量门。
5. 一个关卡节点点亮，能量条增加。
6. 舞台进入下一段背景位置。

声音节点：

- 数字飞出：短促上扬音。
- 门吸收：清脆解锁音。
- 座驾穿门：轻快加速音。
- 节点点亮：奖励铃音。

### 3.3 答错普通题

答错时不做失败惩罚动画，目标时长约 350-600ms：

1. 数字或答案槽轻轻弹回。
2. 能量门不打开，只闪一下暗蓝或橙色边缘。
3. 座驾保持原位，略微刹车或晃动。

声音节点：

- 柔和的“未解锁”音，不使用刺耳错误音。
- 题目反馈语音仍然优先，声音不能覆盖朗读。

### 3.4 连对升级

连对是街机奖励层，不是基础动画。连对越多，普通答对动画越有气势：

- 2 连：门环亮度提升，尾焰变长。
- 3 连：数字飞行轨迹带粒子，背景速度线增强。
- 4 连：能量门出现第二层光环，座驾穿门时有冲击波。
- 5 连或满分：终结技前全场能量满格。

声音节点：

- 连对提示音逐级升调。
- 4 连以上使用更厚的能量充能音。
- 不播放过长音效，避免影响下一题节奏。

### 3.5 第 5 题 Boss 护盾

第 5 题进入 Boss 护盾状态：

1. 舞台压暗，Boss 护盾在能量门前展开。
2. 题目仍在右侧清晰显示。
3. 答对后，答案数字变成光钥匙，先击中护盾。
4. 护盾出现裂纹并破碎。
5. 能量门升级为终结星门。
6. 座驾穿过终结星门，Boss 被净化、弹飞或消散。
7. 进入结果页。

声音节点：

- Boss 登场：低频提示音，短且不吓人。
- 护盾命中：玻璃裂纹或能量碎裂音。
- 终结星门：上扬能量音。
- Boss 完成：胜利短号角或星星雨音。

## 4. 主题适配

五个主题共用“数字钥匙开门”的核心机制，但视觉语义不同。

| 主题 | 门/通道表现 | Boss 护盾表现 | 成功语义 |
| --- | --- | --- | --- |
| 警车追击 | 蓝红警灯能量门 | 路障护盾 | 解锁追踪路线 |
| 急救救援 | 医疗十字光门 | 病毒泡泡护盾 | 打开救援通道 |
| 消防救援 | 水柱圆环门 | 火焰护盾 | 水能量扑灭火焰 |
| 日常交通 | 站台/轨道信号门 | 红灯堵车护盾 | 绿灯放行到站 |
| 太空冒险 | 星门/虫洞 | 陨石能量盾 | 穿越星门抵达下一段 |

主题差异应优先体现在：

- 背景地标。
- 能量门造型。
- 数字飞行颜色。
- 座驾尾迹。
- Boss 护盾材质。
- 声音音色。

不应为每个主题复制一套状态机。

## 5. 视觉结构

左侧舞台建议拆成以下层：

1. **背景层**：主题天空、城市、道路、星空或站台。
2. **深度路线层**：5 个关卡节点和远近透视线。
3. **能量门层**：门环、门心、开门光束。
4. **角色层**：座驾 + 恐龙组合。
5. **Boss 层**：普通状态、护盾状态、破碎状态。
6. **特效层**：答案数字、粒子、尾焰、冲击波。
7. **HUD 层**：能量条、关卡进度。

层级必须避免遮挡右侧题目区。舞台内可以强表现，但题目、数字键盘和 OK 按钮不可被特效覆盖。

## 6. 动效规格

| 动效 | 建议时长 | 触发 | 要点 |
| --- | ---: | --- | --- |
| 舞台待机 | 循环 | 出题时 | 慢、轻、不中断阅读 |
| 数字飞向门 | 300-450ms | 答对 | 路径清楚，数字可辨认 |
| 门解锁 | 280-420ms | 数字命中 | 门环旋转、亮起 |
| 座驾穿门 | 450-650ms | 门打开 | 有尾迹和景深速度感 |
| 节点点亮 | 180-260ms | 穿门后 | 小奖励反馈 |
| 答错弹回 | 350-600ms | 答错 | 柔和，不羞辱 |
| Boss 护盾破裂 | 500-750ms | 第 5 题答对 | 裂纹、碎片、压暗恢复 |
| 终结星门 | 900-1400ms | 最后一题答对 | 本轮最强，但不拖沓 |

减少动态效果模式下：

- 停止循环背景和粒子。
- 只保留节点点亮、能量条变化、Boss 状态切换。
- 单个反馈动画不超过 300ms。

## 7. 声音设计

声音模块应提供一组短音效函数，而不是引入长背景音乐：

- `playNumberLaunch(theme)`
- `playGateUnlock(theme, comboTier)`
- `playGatePass(theme)`
- `playNodeLight(theme)`
- `playSoftLocked(theme)`
- `playComboCharge(theme, comboTier)`
- `playBossShield(theme)`
- `playShieldBreak(theme)`
- `playFinalGate(theme)`
- `playVictoryBurst(theme)`

实现建议：

- 使用 Web Audio API 合成短音效，避免新增大体积音频素材。
- 主题通过振荡器波形、频率、包络、滤波和噪声颜色做差异。
- 所有音效必须受现有静音开关控制。
- 题目朗读优先级高于音效；音效音量要低，时长要短。
- iOS/浏览器自动播放限制下，必须在用户点击开始后才初始化音频上下文。

声音风格：

- 警车：电子警灯感，短促双音。
- 急救：柔和上扬提示音。
- 消防：水流/能量喷射感。
- 日常交通：信号灯、到站铃感。
- 太空冒险：合成器星门感。

## 8. 状态与接口

建议新增舞台动画控制层，避免把复杂动画塞进 `ui.js`：

- `v2/scripts/stage-effects.js`
- `v2/styles/stage.css`
- `v2/styles/stage-motion.css`
- `v2/scripts/sfx.js`

核心接口：

```js
StageEffects.renderStage({ theme, vehicleEmoji, dinoEmoji, index, total, comboTier, isBoss });
StageEffects.playCorrect({ answer, theme, comboTier, isFinal });
StageEffects.playWrong({ theme });
StageEffects.playBossIntro({ theme });
StageEffects.reset();
```

`ui.js` 只负责在答题状态变化时调用接口，不直接管理特效 DOM 的细节。

## 9. 验收标准

1. PC 端 1280x720 下，左侧舞台显著强于当前版本，不能只是 emoji 平移。
2. 孩子从画面能看懂：答案数字打开门，座驾进入下一段。
3. 第 5 题有明显 Boss 护盾和终结星门，不与普通题重复。
4. 连对有逐级增强，但不会遮挡题目和键盘。
5. 音效与关键动作同步，并受静音开关控制。
6. 题目朗读不会被音效打断。
7. 减少动态效果模式下仍能表达进度。
8. 自动化测试覆盖主题配置、音效开关、舞台状态接口和静态 UI 结构。
9. 浏览器验证至少覆盖 1280x720 PC 出题、答对、答错、连对、第 5 题终结流程。

## 10. 非目标

- 不新增题型。
- 不重写车库系统。
- 不引入长背景音乐。
- 不做复杂剧情分支。
- 不为手机端单独做完整舞台重排。
- 不使用会影响题目阅读的全屏遮挡特效。

## 11. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 特效太多导致题目不清楚 | 舞台特效限制在左侧，右侧题目区保持最高层级和清晰背景 |
| 声音打断朗读 | 音效短、低音量，朗读优先，必要时朗读期间压低音效 |
| Web Audio 在浏览器中未初始化 | 在用户首次点击后初始化，失败时静音降级 |
| CSS 动效难以测试 | 将状态类、DOM 结构、motion budget 和模块接口纳入静态/单元测试 |
| 主题实现重复 | 主题只提供配置，状态机和动画流程共享 |

## 12. 推荐实施顺序

1. 抽出舞台结构和主题配置字段。
2. 实现无声音版数字钥匙开门流程。
3. 加入普通答错和连对升级。
4. 加入第 5 题 Boss 护盾终结。
5. 接入 Web Audio 短音效。
6. 做 PC 浏览器 dry-run，调节节奏、层级和音量。
7. 补齐自动化测试。
