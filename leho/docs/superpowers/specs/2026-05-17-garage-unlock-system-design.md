# 设计文档：车库解锁系统（第一期·收集养成骨架）

- 日期：2026-05-17
- 状态：已定稿，待评审
- 范围：仅第一期。第二期（盲盒/扭蛋 + 个人小基地）、第三期（玩法/关卡/内容扩展）各自单独走设计，不在本文档内。

## 1. 背景与现状

游戏是单文件 `index.html`（HTML+CSS+JS 内联），面向一个 **5 岁、不识字、只认数字** 的孩子。两个玩家 PK：乐乐（🦕+🚓，`preferTag: police`）、昊昊（🦖+🚑，`preferTag: ambulance`）。

现有可复用机制：

- 按玩家分的答题记录：`localStorage['dino_math_records']`，`getPlayerStats(playerId)` 派生 `totalStars / totalScore / games` 等。
- 组合头像：`comboAvatar(playerId)` = 座驾 emoji + 恐龙徽章，读自 `PLAYERS[playerId].vehicle` / `.avatar`。所有头像位（选玩家页、答题页、进度条、庆祝、飞车特效）都走它。
- 语音：`speak(text, rate)`（中文 SpeechSynthesis），受静音按钮 `voiceMuted` 控制。
- 动画：canvas 烟花 `startFireworks()` / `launchBurst(x,y)`；全屏飞车特效 `showVehicleRush(emoji, type, combo, onDone)`；统一弹跳曲线 `cubic-bezier(.34,1.56,.64,1)`；`element.animate()` 大量使用。
- 页面切换：`showPage(id)`，`.page.active`。现有页面：start / settings / player / quiz / result / leaderboard。
- 计分：`submitAnswer()` 仅在首次答对时 `score++`（重试答对不重复计分）；`showResult()` 收尾并 `saveRecord()`。

## 2. 目标与非目标

**目标（第一期）**：在不破坏现有 PK/排行榜的前提下，引入一套「双货币 + 解锁换装 + 图鉴」的收集养成闭环，提升长期黏性与新鲜感。

**非目标**：
- 不做连续打卡/签到。
- 不做难度进阶、不引入乘除法（题目永远 20 以内加减）。
- 不做盲盒、个人小基地（第二期）。
- 解锁内容**纯换装**，不引入新故事题库 / 新音效 / 新主题（第三期）。

## 3. 硬性约束（贯穿全部）

- **C1 全程语音**：新界面里所有文字都必须有对应语音（接 `speak()`）。数字可仅视觉呈现；名称、操作、状态必须念出来。孩子不能依赖读字完成任何操作。
- **C2 必须有酷炫动画**：关键时刻（赚币、解锁、装备）必须有和现有烟花/飞车同调性的动画，不是可选润色。
- **C3 星星不受影响**：⭐ 仍由答题记录派生，星星塔 / 称号 / 排行榜逻辑完全不变。

## 4. 货币模型（方案 B·双货币）

- ⭐ 星星：保持现状，纯 PK / 排名 / 称号，**永不消耗**。
- 🪙 金币：新增的可花费货币，答对赚取，仅在车库消费。
- 金币、已解锁、当前装备 —— 全部**按玩家独立**，与现有"按玩家分数据"架构一致。

## 5. 数据模型

新增一个 localStorage 键：`dino_math_garage`

```
{
  "lele":   { coins:Int, ownedVehicles:[emoji...], ownedDinos:[emoji...],
              equippedVehicle:emoji, equippedDino:emoji, migrated:true },
  "haohao": { ...同上 }
}
```

- 读写封装：`loadGarage()` / `saveGarage()` / `getPlayerGarage(playerId)`，缺省结构容错（参考现有 `loadRecords` 写法）。
- **初始化 / 迁移**（每个玩家首次访问 garage 数据时执行一次）：
  - `ownedVehicles = [该玩家默认座驾]`，`ownedDinos = [该玩家默认恐龙]`
  - `equippedVehicle/Dino` = 默认值
  - `coins = min(60, floor(该玩家历史 totalScore × 1))`（老玩家补偿，封顶 60；新玩家自然为 0）
  - `migrated = true`，确保补偿只发一次
- `PLAYERS[playerId].vehicle/.avatar` 退化为"默认/初始值"；运行时头像一律以 garage 的 `equipped*` 为准，缺省回落到 `PLAYERS` 默认。

## 6. 金币赚取（节奏：适中）

- 每道题**首次答对** = +2 🪙（跟随现有 `score++` 时机，重试答对不重复给）。
- 一局**满分**额外 +5 🪙。
- 一局 5 题：全对 = 2×5 + 5 = 15 🪙；平均约 8~12 🪙。
- 接入点：
  - 答对时（`submitAnswer` 正确分支）累加本局金币、触发"飞币"动画（见 §10）。
  - `showResult()` 结算：写入 garage `coins`，满分加成，触发结果页金币动画与语音。

## 8. 装备规则（关键行为）

- 装备的座驾 + 恐龙 = **所有头像位显示的内容**（选玩家页、答题页 player indicator、进度条、庆祝覆盖层、全屏飞车特效里的车）。`comboAvatar(playerId)` 改为读 garage `equipped*`。
- `showVehicleRush` 的车辆 emoji 传当前装备座驾。
- **`preferTag` 与故事/音效不变**：乐乐永远出警车故事题、听警笛 `playPoliceSiren`；昊昊永远急救题、`playAmbulanceSiren`。换装只换"飞过去那辆车的样子"，不动题库与音效系统。这是"纯换装"的定义，也是第一期最小改动面。

## 9. 界面与流程（方案 B）

- **选玩家页**：每张玩家卡片增加 `⭐<总星星>　🪙<金币>` 一行（星星沿用现有 preview，金币新增），并新增按钮「🔧 我的车库」。进入该页时，在现有"谁来挑战"语音后追加播报两人金币（见 §10 语音表）。
- **车库页**（新增 `#garage-page`，每人各自）：
  - 顶部：当前玩家组合头像 + 名字 + `🪙<金币>`。
  - 内容：「座驾」网格 + 「恐龙」网格。每个格子状态三选一：
    1. **正在用**：高亮 + ✓ 标记，点击 → 语音确认当前在用。
    2. **已拥有未装备**：点击 → 装备它（动画 + 语音 + 全头像位刷新）。
    3. **未解锁**：显示 🔒 + 价格。
       - 金币**够**：第一次点 = 语音报价并提示"再点一下就解锁"、该格进入"待确认"高亮态（防 5 岁误触）；第二次点同一格 = 真正解锁（扣币、加入 owned、解锁动画、语音）。点其它格则取消待确认态。
       - 金币**不够**：点击仅语音提示还差多少，不扣不解锁、无待确认态。
  - 本页**同时即图鉴**：未解锁项灰显，一眼看全收集进度。
  - 返回按钮 → 选玩家页。
- **结果页**：在分数下方加一行「本局 +X 🪙」（数字滚动 + 金币雨动画 + 语音）；按钮区新增「🔧 去车库」（进入 currentPlayer 的车库）。金币在 `showResult()` 写入，确保进车库即时反映。
- **清除记录**：现有按钮在清 records/names 的同时，`localStorage.removeItem('dino_math_garage')` 并重置内存，保持"一键重置"语义。

## 10. 全程语音（满足 C1）

所有新增可交互元素与状态变化都有语音。受现有 `voiceMuted` 静音控制（静音时不念，与全局一致）。

| 场景 | 语音文案（示例，实现时用玩家当前名字与真实数字） |
|---|---|
| 进入选玩家页 | 现有"谁来挑战，点击你的头像吧"之后："乐乐有 24 个金币，昊昊有 18 个金币" |
| 点「我的车库」 | "这是乐乐的车库，你有 24 个金币，快来挑一辆车吧！" |
| 点"正在用"的车 | "你正在开消防车，真酷！" |
| 点已拥有未装备 | "这是赛车，点一下就能开它！"（装备后接 §装备语音） |
| 点未解锁·够钱 | "火箭，要 40 个金币，你够啦，再点一下就解锁！" |
| 点未解锁·不够钱 | "火箭要 40 个金币，你还差 16 个，再答对几题就能买啦！" |
| 解锁成功 | "太棒了！火箭是你的啦！" |
| 装备成功 | "换好啦！现在开火箭！呜——" |
| 答对赚币（题中） | 复用现有答对语音，不额外打断；金币靠动画表达 |
| 结果页金币行 | "这一局你赚了 8 个金币！" |

## 11. 酷炫动画（满足 C2）

- **答对赚金币**：题卡飞出 🪙 粒子，抛物线汇聚到角标，金币数字 `+N` 跳动（复用现有粒子/`element.animate` 弹跳风格）。
- **结果页**：金币数字从 0 滚动累加 + 金币雨。
- **车库进场**：格子像勋章柜那样错位弹入（`cubic-bezier(.34,1.56,.64,1)`，按 index stagger）。
- **解锁瞬间（重头戏）**：🔒 碎裂 → 该 emoji 巨大化 + 金色光晕 + 全屏烟花（复用 `startFireworks` / `launchBurst`）→ 紧接一段该车的全屏飞车特效（复用 `showVehicleRush`，车 = 刚解锁那辆）做亮相。
- **装备切换**：旧头像缩出、新头像带光环弹入；所有用到 `comboAvatar` 的位置同步刷新。

## 12. 边界与容错

- 金币不足点解锁：仅语音提示差额，不扣币、不改状态。
- 重复点"正在用"的车：仅语音，无副作用。
- `speechSynthesis` 不可用或静音：界面仍可玩（数字+emoji 视觉可辨），语音静默降级（沿用 `speak()` 现有 guard）。
- garage 数据损坏 / 缺字段：`loadGarage()` 按默认结构容错回填。
- 迁移补偿严格只发一次（`migrated` 标记）。
- 清除记录后：金币归 0、仅默认组合、`migrated` 重置（再次按当时 totalScore=0 计算，自然为 0）。

## 13. 验收标准

1. 新界面**每一处文字**都有对应语音（静音时一致静默）。
2. 赚币、解锁、装备三个关键时刻都有动画，调性与现有一致。
3. ⭐ 星星 / 星星塔 / 称号 / 排行榜行为与改动前完全一致（C3 回归）。
4. 金币 / 解锁 / 装备按玩家完全隔离，互不影响。
5. 装备任意座驾后，所有头像位（选玩家/答题/进度条/庆祝/飞车）一致刷新；故事题与音效仍按 `preferTag`。
6. 纯前端 localStorage，离线可用；老玩家首次进入有一次性补偿且仅一次。
7. 清除记录一键连 garage 一起重置。

## 15. 测试方式

项目为单 HTML、无构建/测试框架（`tests/` 目前为空）。采用**人工验收清单**对照 §13 逐项核对；可借助仓库已有的 Playwright（`.playwright-mcp/`）做关键流程（选玩家→赚币→解锁→装备→刷新头像）的脚本化回归。语音项以"是否调用 `speak` 且文案正确"为可测点。
