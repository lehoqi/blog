# 设计文档：车库解锁系统（第一期·收集养成骨架）

- 日期：2026-05-17
- 状态：已定稿（含深度 review 修订 A/B/C），待评审
- 范围：仅第一期。第二期（盲盒/扭蛋 + 个人小基地）、第三期（玩法/关卡/内容扩展）各自单独走设计，不在本文档内。

## 1. 背景与现状

游戏是单文件 `index.html`（HTML+CSS+JS 内联），面向一个 **5 岁、不识字、只认数字** 的孩子。两个玩家 PK：乐乐（🦕+🚓，`preferTag: police`）、昊昊（🦖+🚑，`preferTag: ambulance`）。

现有可复用机制（含行号）：

- 按玩家分的答题记录：`localStorage['dino_math_records']`，`getPlayerStats(playerId)` 派生 `totalStars / totalScore / games` 等。
- 组合头像：`comboAvatar(playerId)`（:1266）= 座驾 emoji + 恐龙徽章，读 `PLAYERS[playerId].vehicle` / `.avatar`。
- 语音：`speak(text, rate)`（:1352）单条 utterance，**每次调用先 `speechSynthesis.cancel()` 再 80ms 后播——后一句会掐断前一句**；受静音按钮 `voiceMuted` 控制。
- 动画：canvas 烟花 `startFireworks()` / `launchBurst(x,y)`；全屏飞车特效 `showVehicleRush(emoji,type,combo,onDone)`（:1908，**文案与音效写死 police/ambulance**）；`Particle` 类支持 `circle/star/trail`；统一弹跳曲线 `cubic-bezier(.34,1.56,.64,1)`；`element.animate()` 大量使用。
- 头像/车辆的**绕过点**（未走 comboAvatar，改造时必须一并处理）：
  - `renderQuestion`（:1761）`$('progress-dino').textContent = p.vehicle`
  - `submitAnswer`（:2439）`vEmoji = vType==='police'?'🚓':'🚑'` 传给 `showVehicleRush`
  - `submitAnswer` 答错反馈（:2480）`PLAYERS[currentPlayer].avatar` 作前缀
- 页面切换：`showPage(id)`，`.page.active`。现有页面：start/settings/player/quiz/result/leaderboard。
- 计分：`submitAnswer()` 仅首次答对 `score++`；`showResult()` 收尾 `saveRecord()`，可由「自动结束」与「答错后点下一题」两条路径到达。

## 2. 目标与非目标

**目标（第一期）**：在不破坏现有 PK/排行榜的前提下，引入「双货币 + 解锁换装 + 图鉴」收集养成闭环，提升长期黏性与新鲜感。

**非目标**：不做连续打卡/签到；不做难度进阶、不引入乘除法（永远 20 以内加减）；不做盲盒/小基地（第二期）；解锁内容**纯换装**，不引入新故事题库/新音效/新主题（第三期）。

## 3. 硬性约束（贯穿全部）

- **C1 全程语音**：新界面所有文字都有对应语音（经语音队列，§10）。数字可仅视觉；名称/操作/状态必须念出。
- **C2 必须有酷炫动画**：赚币、解锁、装备等关键时刻必须有和现有烟花/飞车同调性的动画，且按 §11 可落地、可验收，不是口号。
- **C3 星星零回归**：⭐ 仍由答题记录派生，星星塔/称号/排行榜行为完全不变。
- **C4 语音是增强、非唯一通道**：SpeechSynthesis 在移动端/iOS 常不稳（异步加载、需手势、缺 zh-CN 音）。UI 必须**仅凭 emoji + 数字 + 颜色 + 锁/勾图标也能完整玩通**，语音失灵或静音时不致不可用。

## 4. 货币模型（方案 B·双货币）

- ⭐ 星星：保持现状，纯 PK/排名/称号，**永不消耗**。
- 🪙 金币：新增可花费货币，答对赚取，仅在车库消费。
- 金币 / 已解锁 / 当前装备 —— 全部**按玩家独立**，与现有按玩家分数据架构一致。

## 5. 数据模型（id 化，杜绝 emoji 编码坑）

**A4**：emoji 有变体选择符等编码差异（如 `🏎️` 含 U+FE0F），直接用 emoji 做 key 与 `.includes` 比较会假阴。故：

- 单一常量 `CATALOG`，每项 `{ id, kind:'vehicle'|'dino', emoji, name, voiceName, price }`。**emoji 与价格全程只在 CATALOG 出现一次**，别处一律用 `id`。
- localStorage 键 `dino_math_garage`：
```
{ "lele":   { coins:Int, owned:[id...], equippedVehicle:id, equippedDino:id, migrated:true },
  "haohao": { ...同上 } }
```
- 读写封装 `loadGarage()/saveGarage()/getPlayerGarage(pid)`，缺省结构容错回填；**任何读取一律经 `getPlayerGarage`，它保证返回已初始化且字段完整的记录（单一入口不变量）**。
- **初始化 / 迁移**（每玩家首次经 `getPlayerGarage` 时一次性执行）：
  - `owned = [该玩家默认座驾 id, 默认恐龙 id]`，`equipped* = 默认 id`
  - `coins = min(60, floor(该玩家历史 totalScore × 1))`（老玩家补偿，封顶 60；新玩家自然为 0）
  - `migrated = true`，确保补偿仅一次
- `PLAYERS[pid].vehicle/.avatar` 退化为"默认初始 id 对应 emoji"；运行时显示一律以 garage `equipped*` 经 CATALOG 解析，缺省回落默认。

## 6. 金币赚取（节奏：适中，A5 幂等）

- 每道题**首次答对** = +2 🪙（跟随 `score++` 时机，重试不重复）。
- 一局**满分**额外 +5 🪙。一局 5 题全对 = 15 🪙，平均约 8~12 🪙。
- **A5 幂等与重置**：本局金币用临时变量 `roundCoins`，在 `startGame()` 与 `score` 一起重置；答对分支累加并触发飞币动画；`showResult()` 结算入 garage `coins`，带「本局已结算」幂等标记，防两条到达路径重复进账。

## 8. 装备规则（关键行为，A2/A3/C3）

- **单一真相源原则**：装备 = garage `equippedVehicle/equippedDino`。所有头像/车辆显示一律经 `comboAvatar` 或 CATALOG 解析；**禁止再直接读 `PLAYERS.vehicle/.avatar` 或写死 🚓/🚑**。
- **A3 必改的三个绕过点**：
  1. `renderQuestion`（:1761）进度条小车 → 取装备座驾 emoji
  2. `submitAnswer`（:2439）传给 `showVehicleRush` 的 `vEmoji` → 装备座驾 emoji
  3. 答错反馈（:2480）前缀恐龙 → 装备恐龙 emoji
- **A2 参数化 `showVehicleRush`**：改签名为接受可选 `{text, sound}`（默认值 = 现有 police/ambulance 文案与警笛，**答题流程零回归**）。换装后答题命中主题题：车辆 emoji=装备座驾，但 `preferTag`/故事题库/警笛/庆祝语**不变**（乐乐永远警车题+警笛，只是飞过去那辆车是装备的）。
- **C3**：`preferTag` 与题库、音效系统一律不动。这是"纯换装"的定义与第一期最小改动面。
- **C3 措辞澄清**：comboAvatar 是唯一真相源，切页时各页 `renderQuestion/updatePlayerIndicator/renderResultPK/renderLeaderboard` 自然重渲染即生效；**装备时只动画车库当前页头像，不得去操作非激活页 DOM**。

## 9. 界面与流程（方案 B）

- **选玩家页**：每张卡片加 `⭐<总星星>　🪙<金币>` 一行（星星沿用现有 preview，金币新增）+ 「🔧 我的车库」按钮。进入该页：语音队列（§10）依次播"谁来挑战…"→两人金币。
- **车库页**（新增 `#garage-page`，每人各自，**亦即图鉴**）：
  - 顶部：当前玩家组合头像 + 名字 + `🪙<金币>`。
  - 「座驾」「恐龙」两组网格。**C4 无字也可辨**：每格含 emoji + 状态图标；锁定项显 🔒 + 价格数字，**买得起价格显绿、买不起显红**；已拥有显 ✓，正在用显高亮光环。
  - 每格三态：
    1. **正在用**：高亮+光环，点击 → 仅语音确认（无副作用）。
    2. **已拥有未装备**：点击 → 立即装备（§11 B3 动画 + 语音）。
    3. **未解锁**：显 🔒+价格。
       - 金币**够（coins ≥ price，C2 含等于）**：第一次点 = 语音报价+"再点一下就解锁"+该格进入「待确认」高亮（防 5 岁误触）；第二次点同格 = **A6 立即提交状态**（扣币、加 owned、存盘）后放解锁动画；点其它格/离开页则取消待确认。
       - **不够**：仅语音提示还差多少，不扣不解锁、无待确认。
  - 返回按钮 → 选玩家页。
- **结果页**：分数下方加「本局 +X 🪙」（数字滚动 + 金币雨 + 语音）；按钮区加「🔧 去车库」（进 currentPlayer 车库）。金币于 `showResult()` 写入，进车库即时反映。
- **清除记录**：现有按钮在清 records/names 的同时 `localStorage.removeItem('dino_math_garage')` 并重置内存，保持一键重置语义。

## 10. 全程语音（满足 C1/C4）

### 10.1 语音队列（A1，必须）

新增最小串行队列 `speakQueue(lines[])`：逐句播报，靠 `utterance.onend`（带超时兜底，防 onend 不触发）推进下一句；受 `voiceMuted` 控制（静音整队跳过）；**用户主动操作（点按钮/选项）才允许打断当前队列并起新队列**。所有"连续多句"场景一律走队列，禁止连续裸调 `speak()` 互相掐断。`speak()` 保留用于单句。

### 10.2 语音文案表

| 场景 | 文案（实现用真实名字与数字；名称取 CATALOG.voiceName） |
|---|---|
| 进入选玩家页 | 队列：「谁来挑战？点击你的头像吧！」→「乐乐有 24 个金币」→「昊昊有 18 个金币」 |
| 点「我的车库」 | 「这是乐乐的车库，你有 24 个金币，快来挑一辆车吧！」 |
| 点正在用的车 | 「你正在开消防车，真酷！」 |
| 点已拥有未装备 | 「这是赛车，点一下就能开它！」→（装备后）装备语音 |
| 点未解锁·够钱（第一次） | 「火箭，要 40 个金币，你够啦，再点一下就解锁！」 |
| 点未解锁·够钱（确认） | 解锁语音（见下） |
| 点未解锁·不够钱 | 「火箭要 40 个金币，你还差 16 个，再答对几题就能买啦！」 |
| 解锁成功 | 「太棒了！火箭是你的啦！」（与解锁动画同步） |
| 装备成功 | 「换好啦！现在开火箭！呜——」 |
| 结果页金币行 | 「这一局你赚了 8 个金币！」（接在现有结果语音之后入队，不掐断） |

## 11. 酷炫动画（满足 C2，可落地可验收）

总原则（A6）：**所有动画纯装饰、非阻塞；状态在触发点已提交；动画被跳过/失败不影响数据**。`prefers-reduced-motion` 时退化为瞬时完成 + 仅语音。

- **B1 飞币（答对，题中）**：独立动画（非径向烟花）。`getBoundingClientRect` 取题卡与金币角标实时坐标（响应式安全）；5~8 个 🪙 绝对定位、沿二次贝塞尔飞向角标、带轻微旋转+拖尾；落点角标"咚"放大弹跳并迸一圈金色 `Particle('star')`；元素用完即清。与现有答对动画序列错峰，不与 celebrate/飞车时序打架。
- **B2 解锁（重头戏·四幕串行，每幕带声，≈3~4s）**：
  1. **锁碎**：🔒 裂成碎片带物理飞散（独立 shard 小动画）。
  2. **聚光登场**：复用 celebrate-overlay 遮罩压暗背景，该 emoji 居中巨大化，背后 CSS conic-gradient 金色光线旋转扫动。
  3. **凯旋驶过**：参数化 `showVehicleRush`，刚解锁那辆车横扫全屏，自定义文案「<名字>是你的啦！」+ 庆祝音（非警笛）。
  4. **烟花收尾**：`startFireworks()` + 解锁语音。
  期间禁用车库点击，结束（含超时兜底）后恢复。
- **B3 装备切换**：旧头像旋转缩出 → 新头像带一圈冲击波环（复用 `showVehicleRush` 的 shockwave 概念）爆入 + "叮——"一声 + 火花；该格常驻发光"正在开"光环。
- **B4 车库进场 + 非读者引导**：格子像勋章柜错位弹入（`cubic-bezier(.34,1.56,.64,1)` 按 index stagger）；**买得起但未解锁的格子持续微微金色呼吸闪**——既酷炫，又在无字下用视觉把孩子注意力引向"你能拿这个"（兼顾 C4）。
- **结果页**：金币数 0→X 滚动 + 金币雨。

## 12. 边界与容错

- **C2** 够钱判定 `coins >= price`（等于也够）。
- 不够钱点解锁：仅语音差额，不扣、不改态、无待确认。
- 重复点正在用的车：仅语音，无副作用。
- **A6** 解锁状态在「第二次点确认」瞬间即提交存盘；动画失败/被 reduced-motion 跳过不影响已解锁事实；动画期禁点 + 超时兜底恢复交互。
- **C4** `speechSynthesis` 不可用/静音/缺音：界面凭 emoji+数字+颜色（绿够/红不够）+锁/勾图标仍可完整操作。
- garage 数据损坏/缺字段：`getPlayerGarage` 按默认结构容错回填；迁移补偿严格一次（`migrated`）。
- 清除记录后：金币 0、仅默认组合、`migrated` 重置（此时 records 已清，重算 totalScore=0 自然为 0）。
- **A1** 语音队列超时兜底：`onend` 未触发时按估算时长跳下一句，防卡队列。

## 13. 验收标准

1. 新界面每处文字都有语音；多句场景经队列**不互相掐断**（A1）；静音时一致静默。
2. 赚币/解锁/装备三关键时刻动画按 §11 落地，调性与现有一致；reduced-motion 下退化不报错、状态正确（A6/C2-anim）。
3. ⭐/星星塔/称号/排行榜与改动前完全一致（C3）。答题主流程语音与飞车特效零回归（A2 默认值）。
4. 金币/解锁/装备按玩家完全隔离；金币每局只入账一次（A5）。
5. 装备任意座驾后，所有头像位（选玩家/答题/进度条/庆祝/飞车/排行榜）一致刷新；含 §8 三个绕过点；故事题与音效仍按 `preferTag`。
6. CATALOG 为 emoji/价格唯一来源，owned/equipped 以 id 比较，无 emoji 编码假阴（A4）。
7. **关闭语音 / SpeechSynthesis 不可用时，仅凭视觉仍能看懂买得起与否并完成解锁、装备（C4）**。
8. 纯前端 localStorage，离线可用；老玩家首次进入一次性补偿且仅一次；清除记录连 garage 重置。

## 14. 可调项（实现/评审期可微调）

- 解锁清单车种/价格（§7）；金币费率、满分加成、迁移封顶（§5/§6）；语音具体措辞（§10.2）；解锁四幕各幕时长（§11 B2）。

## 15. 测试方式（C5）

单 HTML、无构建/测试框架（`tests/` 为空）。

- **可测性改造**：`speak`/`speakQueue` 包一层薄接口便于 spy，断言「按序说了哪些文案」而非听感。
- 状态断言落 `localStorage['dino_math_garage']`（解锁前后 coins/owned/equipped），不依赖动画像素。
- 人工验收清单对照 §13 逐项核对；可用仓库已有 Playwright（`.playwright-mcp/`）脚本化关键流程：选玩家→答对赚币→进车库→（够/不够）解锁→装备→返回答题头像已变；并跑一遍**静音态**验证 C4。
