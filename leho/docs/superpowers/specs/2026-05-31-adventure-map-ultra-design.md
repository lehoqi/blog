# 设计文档：冒险地图 Ultra 动效升级

- 日期：2026-05-31
- 状态：草案，待用户评审
- 分支：`game-upgrade-index-html`
- 关联文档：`docs/superpowers/specs/2026-05-28-themed-adventure-upgrade-design.md`
- 范围：只升级 `index.html` 现有冒险 HUD 的地图表现、答对动效、Boss 场域、音效同步和语音打断规则。不改变一局 5 题、题库、金币、车库、勋章和记录结构。

## 1. 背景

现有冒险升级已经把答题流程改成“当前装备座驾主题冒险 + 第 5 题 Boss”。用户验收后提出两点：

- 语音没有播放完时已经答题，旧语音必须立刻停止，不能压住后续反馈。
- 地图太简陋，需要 A+B 混合，并且动效更加夸张酷炫。

本补充规格把地图从“简单进度条”升级为“主题小世界 + 答对小电影 + Boss 竞技场”。孩子不需要识字，只靠数字点、座驾、Boss、颜色、路线、动画、音效和语音理解进度。

## 2. 目标

- 每个主题都有可辨识的小世界地图，不再只是路线点。
- 每次答对都像一次短电影：充能、弹射、冲刺、撞击、推进。
- 第 5 题进入 Boss 竞技场，视觉强度明显高于普通题。
- 所有爆发段都有同步音效；所有新增文字都有语音。
- 答题语音在提交答案时立即停止，后续动效语音从干净状态开始。
- 地图保持在答题页上方 HUD 内，不遮挡题目数字、输入区和数字键盘。

## 3. 非目标

- 不新增长期章节地图或存档进度。
- 不新增每辆车独立地图；继续按五个 family 出图。
- 不改变数学规则、出题概率、金币/星星/勋章规则。
- 不引入外部音频、图片或复杂引擎。
- 不让动效阻塞状态提交；动画失败不能影响计分和结算。

## 4. 视觉方向：A+B Ultra

采用 A+B 混合：

- **A：主题小世界地图**。HUD 内有场景背景、路线、五个数字点、当前座驾、Boss、能量条和主题地标。
- **B：电影追击动效**。答对时地图不是轻微抖动，而是座驾沿路线大位移冲刺，地图出现速度隧道、路线光束、冲击波、粒子爆炸和轻微震屏。

正式 UI 要比预览稿更克制地嵌入答题页，但动效强度沿用 Ultra 方向：孩子看一眼就知道“答对了、冲过去了、离 Boss 更近了”。

## 5. 五个主题小世界

地图由 `Garage.vehicleFamily(getPlayerGarage(playerId).equippedVehicle)` 自动选择。

| family | 地图场景 | 座驾推进表现 | Boss 场域 |
|---|---|---|---|
| `police` | 城市街道、楼房、路障、红蓝警灯 | 警车弹射，红蓝扫光，路障被冲开 | Boss 点放大为红蓝警戒圈 |
| `ambulance` | 医院通道、急救线、绿色治疗光 | 救护车冲刺，绿色治疗粒子铺路 | 病菌/病毒云进入治疗光环 |
| `fire` | 街区火场、水管、火星和烟雾 | 消防车冲刺，高压水柱扫过路线 | 火焰 Boss 被水柱包围 |
| `everyday` | 城市站点、斑马线、路牌、乘客星星 | 校车/出租车/火车/拖拉机沿路冲刺 | 堵车/路障堆被喇叭波推开 |
| `adventure` | 星空轨道、星门、陨石、星轨 | 火箭/赛车/直升机/飞碟喷焰冲刺 | 陨石 Boss 进入旋转星门 |

每个 family 必须有自己的主色、背景地标、路线风格、Boss 图标、音效参数和语音文案。允许共享 DOM 结构和动画函数，禁止某个 family 退回普通进度条。

## 6. 答对五段爆发

每次首次答对按同一状态机触发五段表现：

1. **断语音 + 充能**：提交有效答案后立即 `stopSpeech()`，停止题目朗读和任何延迟朗读；随后能量条暴涨、当前数字点预热发光，播放短促充能音。
2. **座驾弹射**：当前座驾从上一节点弹射到下一节点，位移必须明显；带尾焰、速度线、路线光束和主题声效。
3. **撞击反馈**：目标数字点放大、冲击波扩散、粒子四散，播放命中音。
4. **地图推进**：已完成节点变成完成态，路线亮起一段，Boss/终点能量出现变化。
5. **短语音反馈**：只播一条短句，如“追近啦！”“急救能量到了！”，不得重启旧题目朗读。

第 1-4 题使用完整五段；第 5 题答对后跳过普通推进尾声，进入 Boss 终结技。

## 7. Boss 竞技场

第 5 题渲染前进入 Boss 竞技场：

- Boss 数字点变大，背景压暗。
- 竞技场环或警报环旋转放大。
- 地图路线变成通向 Boss 的高亮光束。
- 播放 Boss 登场音效。
- 语音队列只播一次：`Boss 出场句 + 当前题目朗读`。

第 5 题答对后：

1. 立即停止题目语音。
2. 座驾执行最大幅度冲刺。
3. Boss 场域爆发：冲击波、粒子、全屏闪光、主题终结音。
4. 接现有全屏 Boss finisher 和通关结算。
5. 胜利语音进入结果语音队列，不与旧题目语音重叠。

Boss 登场每局只出现一次。第 5 题答错后重试时，Boss 场域保持，但不重复大登场。

## 8. 音效设计

每个关键动画必须同步音效：

| 动画节点 | 音效要求 |
|---|---|
| 充能 | 短促上升音，随 streak 提高亮度 |
| 弹射冲刺 | whoosh / 警笛 / 车轮 / 喷焰，按 family 变化 |
| 撞击点 | 低频“砰” + 高频闪光音 |
| Boss 登场 | 警报、鼓点或低频压迫音 |
| Boss 终结 | 爆裂、胜利三音或主题和弦 |
| 奖励结算 | 金币雨、烟花、胜利提示音 |

继续使用 Web Audio 合成，不引入外部音频。音效不受 `voiceMuted` 控制，保持现有警笛行为；语音静音只影响 `speak/speakQueue`。

所有音效函数必须容错：AudioContext 不可用时静默失败，不阻塞动画回调。

## 9. 语音规则

这是硬验收项：

- 提交答案后，先调用 `stopSpeech()` 再进入答对/答错分支，确保旧题目语音停止。
- 所有延迟朗读必须绑定 `speechEpoch` 或等价 token，提交后旧 token 不得再开口。
- 新增 UI 文字必须有对应语音；儿童关键进度不能依赖文字。
- 同一时刻需要多段语音时，必须用一个 `speakQueue([...])` 串行，不得连续裸调 `speak()` 互相取消。
- 答对动效语音必须短，不能盖住下一题题目朗读。
- Boss 登场、最终胜利、奖励播报必须排进同一队列，不能互相抢。

## 10. UI 边界

- 地图仍放在答题页上方，作为 HUD，不覆盖主问题。
- 桌面端 HUD 可较高，展示完整地标、路线和 Boss 场域。
- 移动端 HUD 压缩成电影横条：保留五个数字点、座驾、Boss、能量条和主要爆发，不展示过多地标。
- 粒子、速度线、闪光可以溢出 HUD 少量范围，但不得遮挡答案输入框、确认按钮和数字键盘。
- `prefers-reduced-motion` 下禁用震屏和大位移，保留节点推进、颜色变化、语音和音效。

## 11. 技术接入

### 11.1 主题配置扩展

在现有 `ADVENTURE_THEMES` 上补充地图表现字段：

```js
{
  sceneClass: 'adv-scene-police',
  landmarks: ['building', 'roadblock'],
  routeStyle: 'city-chase',
  chargeSound: playAdventureCharge,
  dashSound: playAdventureBoost,
  impactSound: playAdventureImpact,
  arenaSound: playBossEntranceSound,
  finisherSound: playBossDefeatSound
}
```

字段可以按实际命名调整，但必须保持：五个 family 都有场景 class、Boss 表现、冲刺音效、撞击音效和终结音效。

### 11.2 DOM 结构

冒险 HUD 建议拆成稳定层：

- `adventure-scene`：主题背景和地标。
- `adventure-route`：路线光束和五个数字点。
- `adventure-vehicle`：当前装备座驾。
- `adventure-boss`：Boss 图标和竞技场环。
- `adventure-effects`：粒子、速度线、冲击波。
- `adventure-power`：能量条。

`renderAdventureHud()` 只负责根据当前 family、step、bossShown 渲染状态；动画函数只添加短生命周期 class 或临时效果节点。

### 11.3 动画入口

保留现有冒险状态机，升级动画函数：

- `showAdventureStep(theme, vehicleEmoji, dinoEmoji, step, streak, done)`
- `showBossEntrance(theme, vehicleEmoji, dinoEmoji, done)`
- `showBossFinisher(theme, vehicleEmoji, dinoEmoji, streak, done)`

每个入口必须：

- 在开始时播放对应音效。
- 在结束或超时时调用 `done` 一次。
- 清理临时 DOM 节点和动画 class。
- 不直接改分数、金币、题目索引或 localStorage。
- reduced-motion 下走快速完成路径。

## 12. 测试与验收

### 12.1 自动化检查

新增或扩展现有测试，至少覆盖：

- 提交答案会取消当前语音和延迟语音。
- 旧题目语音在提交后不会恢复。
- 五个 family 都有地图配置和音效配置。
- `renderAdventureHud()` 输出五个数字点、座驾、Boss 和能量条。
- Boss 登场每局只触发一次。
- 答对动画期间重复提交不会重复计分、重复金币或重复结算。

### 12.2 浏览器自检

每个 family 至少手动或脚本验收一次：

1. 装备该 family 座驾后开局，地图皮肤自动变化。
2. 第 1 题答对，确认语音立即停止，充能、冲刺、撞击、节点推进和音效都出现。
3. 连续答对，确认速度、粒子、能量或震屏增强。
4. 到第 5 题，确认 Boss 竞技场出现且不重复大登场。
5. 第 5 题答对，确认终结技、音效、胜利语音和结果页顺序正确。
6. 移动端宽度下，地图不遮挡题目、答案和数字键盘。
7. 静音语音后，视觉仍能看懂进度；音效行为与现有警笛一致。
8. reduced-motion 下，流程正确且不报错。

### 12.3 自检规则

实现完成前必须逐项确认：

- **逻辑是否一致**：错题不推进，首次答对才推进，第 5 题只结算一次。
- **动画是否足够酷炫**：答对至少有充能、冲刺、撞击三类反馈；Boss 至少有场域、震屏/闪光、终结三类反馈。
- **动画是否有音效**：每个关键动画入口都有对应音效调用或明确复用。
- **视觉是否仅仅依赖文字**：关键进度能靠数字点、座驾、Boss、颜色、路线和语音理解。
- **语音是否受控**：提交答案会停止旧语音，延迟语音不会复活，多句语音按队列播放。
- **移动端是否安全**：地图不遮挡数字和按键。
- **五族是否完整**：五个 family 都有小世界、Boss、冲刺、终结、音效和语音。

## 13. 可调项

- 粒子数量、震屏幅度、闪光强度。
- 每段动画时长，建议普通答对 900-1400ms，Boss 终结 1800-2600ms。
- 各 family 具体地标数量。
- 连对增强阈值。
- 语音短句措辞。

默认建议：动效强度按 Ultra 方向做满，但在移动端和 reduced-motion 下自动降档；先确保“酷炫、声音、语音、不卡流程”四件事同时成立。
