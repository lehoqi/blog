# 小恐龙数学冒险 V2 设计文档

## 目标

V2 要把现有游戏从“儿童数学答题页面”升级为“儿童街机闯关游戏”。孩子的主观感受应从“我在做题”变成“我在开车/开火箭冲关、打 boss、赢奖杯”。

核心目标：

- 画面冲击力明显提升，第一屏就像游戏而不是练习页。
- 题目仍然清晰、可读、低干扰，不能因为特效影响答题。
- 答对反馈要有爽感，连续答对要有升级感。
- 满分和解锁奖杯要成为一局的高潮。
- 继续复用现有题库、记录、金币、车库、奖杯逻辑，V2 重点重做表现层和交互编排。

## 设计方向

采用“高饱和街机动画片”风格。

关键词：

- 街机
- 赛道
- 冲刺
- 能量
- boss
- 奖杯
- 儿童动画片

视觉上不要继续受当前绿色卡片页面限制。V2 可以重新设计背景、布局、角色比例、动效节奏和结果页。但数学题、输入区、反馈文字必须保持清晰，不做会遮挡题目的装饰。

## V2 首版规格边界

V2 首版不是重新发明整套数学游戏，而是在 `v2` 下建立独立表现层，同时把已经验证过的题目、奖励和记录规则迁移为可复用模块。

必须保留：

- 一轮 5 题。
- 两个玩家：乐乐、昊昊。
- 混合题型权重：简单题少量出现，进退位题占比最高，缺数题、比较题适中，两步题少量出现。
- 答错后允许继续尝试，不能因为失败中断一局。
- 本地存储记录、金币、车库、奖杯进度。

允许重做：

- 所有页面布局。
- 所有视觉主题、动效、音效编排。
- 结果页奖励展示顺序。
- 首页、玩家选择、奖杯大厅的信息层级。

首版不改变：

- 题目难度范围。
- 金币计算规则。
- 奖杯解锁条件。
- 车库物品价格和默认座驾。

## 体验原则

1. **常态像游戏**
   页面静止时也要有游戏世界感：赛道、能量槽、关卡地图、boss、角色站位都要可见。

2. **关键瞬间爆发**
   强动效集中在开始、答对、连击、最后一题、满分、解锁奖杯。不要让所有元素一直闪，避免疲劳。

3. **学习信息优先**
   题目文字、算式、答案输入、错误提示永远优先于视觉特效。动效不能遮住题目，不能制造误导。

4. **孩子能理解进度**
   每一题答对后，孩子要看得出“我前进了一步”“boss 受到了打击”“能量变强了”。

5. **奖励有层次**
   星星和金币是日常奖励，奖杯是能力里程碑，满分是大结算高潮。

## 页面结构

### 1. 首页：冒险出发大厅

当前首页是标题、两个恐龙 emoji 和开始按钮。V2 首页改成游戏入口。

布局：

- 全屏纵深赛道背景，从底部延伸到远方。
- 两个玩家角色站在赛道前景，座驾和恐龙组合更大。
- 中央标题为“小恐龙数学冒险”，但视觉焦点是角色和赛道。
- 开始按钮设计为街机启动按钮，有发光边缘、按下弹跳和短促冲击波。
- 设置、排行榜入口降级为较小的图标按钮，避免抢主按钮注意力。

动效：

- 背景赛道缓慢流动。
- 角色轻微待机动作。
- 点击开始后，屏幕出现“出发！”转场，当前玩家座驾冲进赛道。

成功标准：

- 打开首页 1 秒内能感到这是游戏。
- 孩子能立刻找到“开始冒险”。
- 装饰不挤压移动端空间。

### 2. 玩家选择页：角色登场

当前玩家选择是两张卡片。V2 改成“选择出赛车手”。

布局：

- 两个玩家以左右对战位展示。
- 每个玩家显示：角色组合、名字、星星、金币、最近 3 个奖杯。
- 卡片改成角色站台，不做普通白卡片。
- 车库入口保留，但作为站台上的工具图标。

动效：

- hover 或点击时角色向前一步，座驾灯光亮起。
- 选中后角色放大，另一个角色退到背景。

成功标准：

- 两个孩子的身份和成绩清楚。
- 选择动作有仪式感。

### 3. 答题页：战斗驾驶舱

这是 V2 的重点。

布局分三层：

- 上层：动态关卡舞台
  - 显示赛道、当前座驾、boss、路线点、能量槽。
  - 主题随座驾变化：警车追击、救护通道、消防救援、日常交通、太空冒险。

- 中层：题目区
  - 题目故事和算式居中展示。
  - 文字大、对比强、背景干净。
  - 缺数题的问号可有轻微呼吸动画。

- 下层：控制台数字键盘
  - 数字按钮像控制台按键。
  - OK 按钮是主操作，颜色和尺寸更突出。
  - 删除按钮明显但不刺眼。

交互：

- 答对后座驾向前冲一段，路线点点亮，boss 受击。
- 答错第一次：轻微抖动，鼓励再想想。
- 答错第二次：给动态范围提示，不能沿用旧的 20 以内假设。
- 多次答错：显示正确答案，但仍允许孩子重新输入并完成推进。

连击系统：

- 1 连：普通冲刺。
- 2 连：速度线增强。
- 3 连：屏幕短震、残影增加。
- 4 连：能量爆亮，boss 明显受击。
- 5 连或最后一题：终结技。

成功标准：

- 答题期间题目始终清晰。
- 答对反馈足够强，但时长不拖慢节奏。
- 连击升级肉眼可见。

### 4. 题型专属反馈

V2 不只告诉孩子“答对了”，还让不同能力有不同表现。

题型反馈：

- 进退位题：引擎喷火、速度线、加速音效。
- 缺数题：拼图块归位，问号变成答案光点。
- 比较题：高低数量柱、差值光带或雷达锁定发光。
- 两步题：能量蓄满后释放超级冲刺。
- 简单题：轻快推进，不抢高级题的表现。

这些反馈只作为答对后的表现，不改变题目本身。

成功标准：

- 孩子能逐渐感到不同题型代表不同能力。
- 不用在界面上解释规则，视觉本身能表达。

### 题型准确性和视觉禁忌

V2 的画面可以更夸张，但题目文案、算式方向和视觉暗示必须精确。所有题型都要满足“故事里问什么，算式就表达什么，视觉也不能暗示另一个概念”。

通用要求：

- 题目故事、问题句、算式、朗读文本必须指向同一个答案。
- 视觉反馈只能在答对后出现，不能在答题前暗示答案。
- 错误提示只能缩小思考范围，不能把旧的 20 以内上限写死。
- 答案显示后仍允许孩子重新输入并完成推进。

各题型要求：

| 题型 | 必须准确表达 | 禁止出现 |
| --- | --- | --- |
| 简单题 | 加法表示合起来，减法表示拿走或剩下。 | 用冲刺动画改变题意，或把减法说成“多了”。 |
| 进退位题 | 仍然是普通加减法，只是数值更难。 | 在文案里说“进位”“退位”要求孩子理解术语。 |
| 缺数题 | 问号必须对应未知项，不一定是最终结果。 | 把 `? + b = total` 朗读成“total 等于多少”。 |
| 比较题 | 明确谁比谁多、差多少。 | 用“天平平衡”当主视觉，避免误导成两边相等。 |
| 两步题 | 两个动作顺序必须和算式顺序一致。 | 只展示最后一步，导致孩子忽略第一步。 |

比较题首选视觉：

- 两条数量轨道，一条高、一条低，中间差值光带亮起。
- 或高低柱状能量槽，答对后差值部分飞入能量槽。
- 可以用雷达锁定“差值目标”，但不要用平衡态作为主反馈。

### 5. 结果页：胜利舞台

当前结果页偏统计。V2 结果页改成一局的结算高潮。

布局：

- 中央大角色站上胜利台。
- 分数、星星、金币、奖杯分层出现。
- 满分时显示大标题：“完美通关”。
- 非满分时仍显示积极反馈，但视觉强度略低。

动效：

- 星星先飞出。
- 金币再落入钱袋或计数器。
- 新奖杯最后从上方落下，砸出光环。
- 满分触发全屏烟花和舞台灯。

结果信息：

- 本局答对数。
- 本局获得金币。
- 新解锁奖杯。
- 本局能力亮点，例如“进退位题全对”“完成两步题”。

奖励展示顺序：

1. 分数和通关状态先出现，让孩子知道这一局完成了。
2. 星星出现，作为本局表现反馈。
3. 金币进入计数器，作为可消费奖励。
4. 新能力奖杯出现，作为结算主视觉。
5. 普通勋章出现，作为次级提示。

如果同一局同时解锁多个奖励，优先级如下：

1. 本局直接相关的能力奖杯，例如进退位、缺数、比较、两步、全能。
2. 满分或连胜奖杯。
3. 车库收集类勋章。
4. 累计次数、累计星星、累计金币类勋章。

成功标准：

- 满分要明显比普通完成更震撼。
- 新奖杯不能只是列表项，必须是结算主视觉之一。
- 普通勋章不能抢走能力奖杯的视觉焦点。

### 6. 奖杯与成就大厅

当前排行榜和奖杯柜可以保留逻辑，但视觉重做。

布局：

- 两个玩家各有一块奖杯展示架。
- 星星塔作为长期进度，不是唯一主角。
- 奖杯按能力分组：连胜、进退位、缺数、比较、推理、全能。
- 未解锁奖杯显示剪影和简短目标。

成功标准：

- 孩子能看到“我已经拿到了什么”。
- 未解锁目标能引导继续玩，但不制造压力。

### 奖杯和勋章语义

V2 内部可以继续使用现有 `ALL_MEDALS` 数据，但展示语义要区分：

- **奖杯**：能力里程碑，优先展示，通常来自 `trophy_` 开头的解锁项。
- **勋章**：长期收集和累计进度，作为奖杯大厅里的丰富内容。
- **星星**：本局表现和长期 PK 的基础分。
- **金币**：车库消费资源。

孩子第一眼应该看到“我掌握了什么能力”，其次才是“我累计玩了多少次”。

## 主题系统

V2 保留现有车库和座驾主题，但让主题更影响画面。

主题：

- 警车：夜间城市追逐，红蓝灯、路障、boss 逃跑。
- 救护车：绿色生命通道，医院、急救包、清障。
- 消防车：火场救援，水柱、火焰、消防站。
- 日常车：城市交通任务，公交站、斑马线、红绿灯。
- 冒险车：太空赛道，星门、陨石、轨道光束。

座驾主题映射：

| 座驾 | 主题 | 视觉关键词 |
| --- | --- | --- |
| 警车 | 警车追击 | 夜间城市、红蓝警灯、路障 boss。 |
| 救护车 | 急救救援 | 绿色生命通道、医院、急救包、病毒云。 |
| 消防车 | 消防救援 | 火场、水柱、消防站、火焰 boss。 |
| 校车、出租车、火车、拖拉机 | 日常交通 | 公交站、斑马线、红绿灯、堵车障碍。 |
| 赛车、直升机、火箭、飞碟 | 冒险车 | 赛道、星门、陨石、轨道光束。 |

每个主题至少包含：

- 背景色和光效。
- 路线样式。
- boss 或障碍物。
- 答对冲刺音效类型。
- 终结技视觉差异。

## 动效系统

动效分为四级，避免无节制堆特效。

### 低级动效：常态

- 背景轻微流动。
- 角色待机。
- 路线点呼吸。
- 能量槽轻微发光。

### 中级动效：答对

- 座驾推进。
- 路线点点亮。
- 小粒子和金币飞出。
- boss 小受击。

### 高级动效：连击

- 全屏速度线。
- 角色残影。
- 屏幕短震。
- 能量槽爆亮。

### 最高级动效：终结和满分

- boss 终结动画。
- 奖杯降落。
- 全屏烟花。
- 舞台灯光。

减少动效模式：

- 必须支持 `prefers-reduced-motion`。
- 降低动效时保留进度变化和奖励信息，但关闭屏幕震动、全屏速度线、大量粒子。

时间和性能预算：

| 场景 | 标准模式 | 减少动效模式 |
| --- | --- | --- |
| 首页待机循环 | 持续轻动画，不闪烁。 | 背景静态，保留按钮状态。 |
| 点击开始转场 | 不超过 900ms。 | 不超过 300ms，直接进入玩家选择或答题。 |
| 答错反馈 | 不超过 600ms。 | 不超过 250ms，只保留颜色和文案变化。 |
| 普通答对推进 | 900ms 到 1500ms。 | 不超过 400ms，路线点直接点亮。 |
| 3 连以上答对 | 1200ms 到 1800ms。 | 不超过 500ms，保留能量槽变化。 |
| 最后一题终结技 | 不超过 2200ms。 | 不超过 700ms，boss 状态直接完成。 |
| 满分奖杯结算 | 主要信息 500ms 内出现，完整庆祝不超过 2800ms。 | 主要信息立即出现，庆祝不超过 700ms。 |

粒子和震动限制：

- 手机竖屏一次答对粒子不超过 35 个。
- 桌面一次答对粒子不超过 80 个。
- 屏幕震动只在 3 连以上或终结技出现，单次不超过 180ms。
- 不使用高频闪烁；同一区域亮暗切换频率不能让人感到刺眼。

## 声音设计

声音不作为必须条件，但 V2 可以强化已有音效。

声音类型：

- 按钮点击：短促、清脆。
- 答对：上扬音阶。
- 答错：轻微低音，不刺耳。
- 连击：逐步升高。
- boss：低频提示。
- 满分：短庆祝旋律。

音量和静音：

- 保留静音按钮。
- 语音朗读优先级高于音效。
- 音效不能盖住题目朗读。

## 数据和逻辑复用

V2 应优先复用现有逻辑：

| 能力 | 现有来源 | V2 处理方式 | 不允许 |
| --- | --- | --- | --- |
| 题型权重和统计 | `logic/question-mix.js` | 直接复用或迁移为同名纯逻辑模块。 | 在 UI 里重新写一套权重。 |
| 题目生成模板 | `index.html` 里的生成函数 | 迁移到 `v2/scripts/questions.js`，保持测试覆盖。 | 改文案后不补模板测试。 |
| 冒险 run 状态 | `adventure.js` | 复用状态机概念，V2 可扩展视觉状态。 | 用 DOM 状态判断题目是否已结算。 |
| 车库和金币 | `garage.js` | 直接复用规则和价格。 | 改金币算法或物品价格。 |
| 玩家记录 | `index.html` 的 localStorage 记录结构 | 保持兼容，必要时只加字段不删字段。 | 破坏旧记录读取。 |
| 奖杯和勋章 | `ALL_MEDALS` 和 `QuestionMix` 统计 | 迁移到 `rewards.js`，保留解锁条件。 | 把奖杯展示顺序等同于数据定义顺序。 |
| 语音朗读 | `speak` / `speakQueue` 模式 | 保留可取消队列和静音开关。 | 新一轮开始后继续朗读旧结果。 |

V2 主要新增或重构：

- 视觉状态模型。
- 页面布局组件。
- 动效编排。
- 主题渲染配置。
- 结果页奖励编排。

迁移原则：

- 先迁移纯逻辑，再重做视觉。
- 每迁移一个逻辑模块，都要有对应单元测试。
- 表现层可以大改，但结果数据必须和旧版一致。
- `index.html` 旧版保留为对照基线，V2 在 `v2` 内独立开发。

## 建议文件结构

后续实现建议在 `v2` 下独立开发。

推荐结构：

```text
v2/
  DESIGN.md
  index.html
  styles/
    base.css
    arcade.css
    themes.css
    motion.css
  scripts/
    game-state.js
    questions.js
    rewards.js
    themes.js
    motion.js
    ui.js
  tests/
    question-copy.test.js
    reward-flow.test.js
    smoke.test.js
```

说明：

- `questions.js` 迁移现有题库逻辑，并包装 `QuestionMix`。
- `rewards.js` 负责星星、奖杯、记录和结果页奖励排序；金币规则仍以 `Garage.roundCoins` 为准。
- `themes.js` 负责座驾主题配置，映射关系要和车库一致。
- `motion.js` 只做动效编排和时间预算，避免散落在业务逻辑里。
- `ui.js` 负责页面切换和 DOM 渲染。
- `game-state.js` 保存当前局状态，不直接保存 DOM 引用。

## 实现阶段

### 阶段一：V2 骨架和核心答题页

目标：

- 建立 `v2/index.html` 和基础模块。

## 测试策略

自动测试：

- 题目文案和算式方向一致。
- 缺数题、比较题、两步题答案准确。
- 答错提示范围不写死旧上限。
- 奖杯解锁条件准确。
- 记录和金币结算幂等。

浏览器测试：

- 首页首屏无重叠。
- 答题页移动端不遮挡题目。
- 答对动画后能进入下一题。
- 满分结果页正确展示奖杯。
- `prefers-reduced-motion` 下无强震动或大量粒子。
- 新一轮开始后旧朗读和旧动效不继续播放。

视觉检查：

- 桌面宽屏。
- 普通手机竖屏。
- 小屏手机竖屏。
- 横屏高度不足场景。

固定视口验收：

| 视口 | 要求 |
| --- | --- |
| 390 x 844 | 不滚动即可看到舞台、题目、答案、数字键盘和 OK 按钮。 |
| 360 x 640 | 舞台压缩为紧凑模式，题目和键盘优先完整显示。 |
| 430 x 932 | 允许更强舞台表现，但题目区不能被压小到难读。 |
| 812 x 375 横屏 | 可以使用横向紧凑布局，不能让键盘或 OK 按钮掉出屏幕。 |
| 1280 x 720 | 舞台视觉要足够强，不能只把手机布局居中放大。 |

题型模板测试：

- 简单题：加法、减法各至少 20 个样本，故事和答案一致。
- 进退位题：加法必须产生 10 以上结果，减法必须涉及借位场景。
- 缺数题：四种未知位置都要覆盖。
- 比较题：`A 比 B 多多少` 和反向故事都要覆盖。
- 两步题：`+ -` 和 `- +` 都要覆盖。
- 所有题型都要验证 `equationParts`、`readEquation`、`answer` 三者一致。

## 风险和约束

风险：

- 视觉重做可能让题目不够清晰。
- 动效过长会拖慢答题节奏。
- 过多粒子可能影响低性能设备。
- 如果一次迁移全部逻辑，容易引入记录和奖励回归。
- 复用旧逻辑但重做展示时，奖杯和勋章语义可能再次混淆。
- 题型专属视觉如果过于抽象，可能让孩子误解数学关系。

控制方式：

- 先做答题页和结果页，不先重做全部页面。
- 保留现有题库和奖励逻辑作为基线。
- 每阶段都跑自动测试和浏览器 smoke test。
- 动效分级，并支持减少动效。
- 每个视觉反馈都要先过文案和数学含义 review。
- 新增动效前先确认它不会遮挡题目、答案和 OK 按钮。

## 不做范围

V2 首版不做：

- 新数学知识点。
- 多人实时对战。
- 后端存储。
- 复杂剧情系统。
- 需要下载大量图片资源的美术包。

首版重点是把现有游戏体验做得更像游戏，而不是扩大功能范围。

## 成功标准

V2 首版完成后应满足：

- 首页一眼看起来是儿童街机游戏。
- 答对一题有明显爽感。
- 连续答对有升级感。
- 满分结算让孩子期待再来一局。
- 题目文字始终清楚、不被特效干扰。
- 现有题库、记录、车库、奖杯逻辑不退化。
